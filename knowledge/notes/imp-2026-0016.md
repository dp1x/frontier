# imp-2026-0016 — BlockstreamResearch/bip-frost-dkg (Python)

## Why this candidate

The `bip-frost-dkg` repo is the most spec-authoritative FROST-DKG
reference available. It is maintained by Tim Ruffing (real-or-random),
the primary author of the FROST-DKG BIP and one of the editors of
RFC 9591. The repo:

- Serves as the source-of-truth test-vector generator for the FROST-DKG
  BIP and is consumed by external reviewers (including ZcashFoundation/frost
  and frost-rerandomized).
- Implements only the DKG half of FROST; the signing half is intentionally
  out of scope.
- Covers secp256k1 only (ed25519 variant is in a separate draft).

## Internal implementation choices (audit-relevant)

- **Curve**: secp256k1 only (per BIP scope).
- **Participant index encoding**: 1-indexed positive integer in
  [1, num_participants] (per RFC 9591 §4.2). Encoded as a single byte
  in protocol messages (BIP caps num_participants at 255 for the python
  reference).
- **DKG polynomial evaluation**: Horner evaluation for VSS verification
  (not Lagrange — Lagrange is used only at signing time, out of scope
  here).
- **Commitment serialization**: byte-identical to RFC 9591 §4.2
  commitment list layout.
- **No external crypto deps**: uses hashlib + pure-Python secp256k1
  arithmetic for transparency and verifiability.

## Existing test infrastructure

- `vectors/` directory at the repo root (post-2026-07-30 layout; was
  previously nested under `python/`). JSON files with one KAT per scenario.
- Test vector coverage includes: valid DKG happy-path; share-verification
  failures (VSS mismatch); duplicate-share detection (equivocation);
  missing-share reconstruction failures; complaint round mechanics.
- Cross-consumed by `ZcashFoundation/frost` and `frost-rerandomized`
  for conformance testing.

## Lineage

Independent lineage. Clean-room Python reimplementation of the FROST DKG
protocol by the BIP authors. Not a port of `frost-rs` or any other Rust
crate. Shares only the *specification* (RFC 9591 + FROST-DKG BIP draft)
with the Rust crate family, not source code.

## Audit-role notes

For msn-2026-0013, this repo validates:

- (a) DKG round produces correct KeyPackages that are accepted by a
  downstream FROST signing crate.
- (b) Commitment-list serialization matches RFC 9591 §4.2 byte-for-byte.
- (c) Participant_index encoding matches what `ZcashFoundation/frost`
  produces.

The signing half of FROST is NOT in this repo; cross-impl byte-exact
comparison for the signing round requires pairing this repo's DKG output
with a separate FROST signing implementation.
