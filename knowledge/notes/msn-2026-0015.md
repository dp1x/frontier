# Mission note: msn-2026-0015 - CBOR §4.2 cross-impl conformance

## Summary

Established the Frontier CBOR §4.2 cross-implementation conformance matrix
framework. Built cleanroom Python oracle, adversarial vector generator,
per-library adapter, matrix runner, and reproducer. Ran matrix against
1 library (cbor2 6.1.4) producing 222 cells with 88.7% PASS rate.

Identified real cross-impl divergence: cbor2's canonical mode implements
RFC 8949 §4.2.1 (core deterministic bytewise lex sort) while Frontier's
cleanroom oracle implements §4.2.3 (length-first sort). Both rules are
normative in RFC 8949. Documented as fnd-2026-0013 (candidate, awaiting
cohort expansion).

Terminal status: inconclusive-after-budget with positive methodology
contribution.

## What was actually done

1. **Scout synthesis** (front of session): 6 parallel scout reports
   commissioned for CBOR/COSE/WebAuthn, QUIC retry, X.509 path validation,
   C23 _BitInt, DNS/DNSSEC, WebAuthn attestation. Selection: CBOR/COSE

4. **Cleanroom Python oracle** (cbor-cross-impl/oracle/cbor_oracle.py):

5. **Adversarial vector generator** (cbor-cross-impl/vectors/gen_vectors.py):

6. **Library adapter layer** (cbor-cross-impl/adapters/):

7. **Matrix runner** (cbor-cross-impl/runner/run_matrix.py):
   - Orchestrates (library × axis × vector × mode) sweep

9. **Verifier** (vrf-2026-0014): 4-step deterministic verification of

## Results

Matrix: 222 cells, 197 PASS, 18 SPEC_AMBIGUITY, 3 SPEC_VIOLATION,
2 INTEROP_BREAK, 2 ERROR.

Real findings:
- **fnd-2026-0013 (candidate)**: cbor2 canonical mode uses RFC 8949
  §4.2.1 bytewise lex sort; oracle uses §4.2.3 length-first sort.
  Documented divergence. NOT a spec violation.

Methodological observations:
- cbor2 default mode uses IEEE 754 double-precision for ALL floats
  (documented behavior; canonical=True required for shortest-form)
- 4 vector-generator issues produced false-positive divergences that
  were separated from real findings

## Methodological lessons

1. **JSON serialization is lossy for non-string dict keys.** The vector
   generator initially converted int keys to strings, losing information
   about map_key_sort semantics. Fixed with `__type__: "dict_int_keys"`
   sidecar pattern.

2. **"Tagged value" representation ambiguity.** Using a tuple `(tag, content)`
   for tagged values conflicts with using tuples as array keys. Solved with
   a `Tagged` wrapper class.

3. **Two equally-valid interpretations of RFC 8949 §4.2.** The bytewise-lex
   (§4.2.1) and length-first (§4.2.3) sort orders are both normative.
   Cross-impl matrices MUST specify which they use.

4. **Default-mode vs canonical-mode divergence.** cbor2's default mode
   is non-canonical (uses double-precision floats, non-deterministic
   map ordering). Canonical mode is required for §4.2 conformance.
