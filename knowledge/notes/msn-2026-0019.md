# msn-2026-0019 — FROST (RFC 9591) Threshold Signature Audit

## Mission Status

**Status**: active (Phase 1 — pre-work / cleanroom extension design)
**Activated**: 2026-09-02

## Selection Rationale

After msn-2026-0018 (COSE message-encoding conformance) reached verified
terminal state with `fnd-2026-0014` promoted (pycose tstr-only sort bug),
a bounded opportunity scan was run. The strongest candidate was the
FROST (RFC 9591) cross-implementation byte-exact differential because:

1. **Inheritance from a proven harness.** Frontier's CBOR (msn-2026-0015
   to 0017) and COSE (msn-2026-0018) missions established a reusable
   byte-exact differential harness pattern (cleanroom + adapter + matrix
   runner + TSV/JSONL + verdict classification). The FROST mission
   inherits this pattern verbatim.

2. **Cleanroom oracle + KAT vectors already on disk.**
   `crypto/frost-cross-impl/cleanroom/frost_cleanroom.py` exists with
   `secp256k1_sha256` reference implementation against
   `kat/rfc9591_appendix_e5_secp256k1.json` (matching the
   ZcashFoundation/frost-rs KAT JSON shape). `kat/rfc9591_appendix_e1_ed25519.json`
   is also already on disk. The cleanroom currently verifies only up
   to `binding_factor` — extending it to `signature_share` and
   `aggregate (R, z)` requires secp256k1 point addition (the existing
   code calls out this gap explicitly).

3. **Lineage-independence ceiling is 2-3.** `frost-rs` (ZCashFoundation
   Rust, production) + `frost` (ZKSecurity Go, reference) +
   cleanroom oracle gives a 3-implementation cohort spanning 2
   languages and 2 author lineages. The CBOR cohort achieved
   verified_conclusion with 3 independent lineages (oracle + cbor2 +
   ciborium) — FROST will likely achieve the same.

4. **Lightweight compute.** frost-rs `cargo build --release` <60s;
   frost Go `go build ./...` ~5s; cleanroom runs in seconds. Total
   wall clock for full matrix <5 min.

5. **Genuinely new family.** Threshold signatures are a different
   primitive family from anything Frontier has covered (KEMs,
   encryption envelopes, single-party sigs via X-Wing).

6. **Discovery potential.** RFC 9591 has at least 4 latent divergence
   classes (participant encoding, binding_factor domain-separation
   string variants, transcript-commitment ordering, Lagrange basis
   implementation method).

## Methodology Notes

Per the FROST scout dossier (`knowledge/notes/scout-frost-2026-08-31.md`):

- **H1 (most likely, positive):** All three implementations agree
  byte-exactly on RFC 9591 Appendix A KAT vectors for both
  ciphersuites. Outcome: discovery-grade positive finding.
- **H2:** All agree on positive KAT but diverge on at least one
  negative stimulus (e.g., nonce reuse, off-curve R). Outcome:
  interop-note finding.
- **H3:** At least one implementation produces byte-different output
  on KAT vectors (e.g., binding factor domain-separation variant).
  Outcome: spec-compliance-gap finding.
- **H4:** None match exactly because RFC 9591 §4.2 leaves a
  parameter informative. Outcome: clarification request.
- **H5:** Implementations disagree on malformed input acceptance.
  Outcome: interoperability-gap finding.
