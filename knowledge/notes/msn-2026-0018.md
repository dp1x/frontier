# msn-2026-0018 — COSE Message-Encoding Conformance Matrix

## Mission Status

**Status**: verified  
**Terminal**: 2026-09-02  
**Finding**: fnd-2026-0014 promoted to verified_conclusion

## Summary

Built and ran a COSE message-encoding conformance matrix across 2 lineage-independent libraries (pycose 1.1.0, go-cose 1.3.0), 40 vectors, 10 audit axes. Promoted one verified finding: **pycose does NOT sort map keys per RFC 8949 §4.2.1 bytewise-lex for tstr-only maps** (a real SPEC_VIOLATION per RFC 9052 §9).

## What Was Actually Built

1. **Cleanroom Python oracle** (`cose-cross-impl/oracle/cose_oracle.py`) implementing RFC 9052/9053 §3-§6 message structures. **5 distinct bugs found and fixed during the session**:
   - Wrong context string ('Encrypted' → 'Encrypt0' per RFC 9052 §5.3)
   - Treating str as bstr in CBOR encoding (loses tstr/bstr distinction)
   - Double bstr wrapping (encoder wrapping already-wrapped bytes)
   - §4.2.3 length-first vs §4.2.1 bytewise-lex sort (added canonical mode to CBOR oracle)
   - `skip_alg_header` not honored by vector generator

2. **Vector generator** (`cose-cross-impl/vectors/gen_vectors.py`): 40 vectors across 10 axes (deterministic seed `0xC0DE0CB0`)

3. **Matrix runner v2** (`cose-cross-impl/runner/run_matrix.py`): Two-level comparison (structure bytes + full message bytes), TSV + JSONL output

4. **Two working adapters**:
   - `lib_pycose_adapter.py`: in-process, extracts pycose internals
   - `lib_go_cose_adapter.py`: shell-out to locally-built Go driver at `R:/cose-cohort/go-cose/driver/driver.exe`

5. **Implementation archaeology** for 5 libraries (4 from subagent + 1 from this session):
   - imp-2026-0020 coset (Google, Rust, ciborium)
   - imp-2026-0021 go-cose (Veraison, Go, fxamacker/cbor)
   - imp-2026-0022 cose-c (COSE WG, C/C++, cn-cbor)
   - imp-2026-0023 cose-java (COSE WG, Java, PeterO CBOR)
   - imp-2026-0024 pycose 1.1.0 (Timothy Claeys, cbor2)
